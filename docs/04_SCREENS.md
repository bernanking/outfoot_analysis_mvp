# 메뉴와 화면 명세

화면별 상세 내용, 행동, 상태 구성은 [프론트 화면별 내용 구성 계획](18_FRONTEND_SCREEN_CONTENT_PLAN.md)을 따릅니다.

## 메뉴 구조

| 사용자 | 메뉴·화면 | 목적 |
| --- | --- | --- |
| 시술자 | 로그인 | 계정 인증 |
| 시술자 | 상담 목록 | 진행상태·담당자·주의신호 기준 조회 |
| 시술자 | 환자 목록·상세 | 환자 검색, 기본정보, 회차 이력 |
| 시술자 | 상담 작업 | 사전답변, 방문정보, 사진·발도장, 분석, 최종 결과를 한 화면에서 처리 |
| 관리자 | 위 메뉴 + 사용자 관리 | 계정 발급·상태·초기화 |
| 관리자 | 기록 관리 | 전체 상담·감사기록 조회와 사유가 있는 삭제 |
| 환자 | 사전질문지 | 링크로 동의·공통·분기 질문 제출 |

별도의 ‘검사 이력’ 메뉴를 중복 생성하지 않습니다. 환자 상세의 회차 목록에서 상담 상세를 엽니다.

### 전역 내비게이션

로그인 후 첫 화면은 별도 대시보드가 아니라 `상담 관리`로 합니다. 초기 정적 화면에서 근거 없는 통계 카드나 차트를 만들지 않고, 사용자가 가장 자주 시작하는 상담 목록을 진입점으로 사용합니다.

```text
OUTFOOT
├─ 상담 관리
│  ├─ 상담 목록
│  └─ 신규 상담 접수
├─ 환자 관리
│  ├─ 환자 목록
│  └─ 신규 환자 등록
└─ 운영 관리                         관리자에게만 표시
   ├─ 사용자 관리
   └─ 기록 관리
      ├─ 상담 기록
      └─ 감사 기록
```

- `상담 관리`는 진행 중인 상담과 종결된 상담을 상태 필터로 함께 조회합니다.
- `환자 관리`는 환자 기본정보와 환자별 상담 회차 진입점입니다. 별도의 검사 이력 메뉴를 만들지 않습니다.
- `운영 관리`는 관리자에게만 표시합니다. 기록 관리는 삭제된 상담 포함 조회·논리삭제와 주요 행위의 감사기록 조회를 위한 운영 화면입니다.
- 기관명, 현재 사용자, 역할, 로그아웃은 상단 사용자 영역에 두며 전역 메뉴 항목으로 만들지 않습니다.
- 고객 안내 인쇄와 삭제 확인은 각각 상담 화면과 기록 관리 화면에서 여는 보조 화면입니다.
- 환자 질문지는 상담별 공개 링크로만 접근하며 시술자용 전역 메뉴를 표시하지 않습니다.

### 상담 작업 내비게이션

상담 하나를 연 뒤에는 아래 다섯 탭을 동일한 순서로 유지합니다. 탭은 작업 순서를 안내하지만, 권한과 저장 상태가 허용하면 이전 단계로 이동할 수 있습니다.

```text
사전답변 → 방문상담 → 사진·발도장 → 분석·보완 → 최종결과
```

`상담 목록 → 상담 접수 → 상담 작업`과 `환자 목록 → 환자 상세 → 회차 선택 → 상담 작업` 두 경로가 같은 상담 화면으로 연결됩니다. 접수 링크 발급 상태는 상담 접수 화면에서 관리하고, 제출된 답변은 상담 작업의 `사전답변` 탭에서 읽습니다.

### 프론트엔드 경로 설계

| 영역 | 화면 ID | 경로 | 연결되는 주요 화면 |
| --- | --- | --- | --- |
| 인증 | S01 | `/login` | 성공 시 `/consultations` |
| 상담 관리 | S02 | `/consultations` | 신규 접수, 상담 작업, 환자 상세 |
| 상담 접수 | S05 | `/consultations/new` | 환자 선택·등록 후 링크 발급 |
| 상담 접수 상세 | S05 | `/consultations/:consultationId/intake` | 링크 복사·재발급, 사전답변 탭 |
| 사전답변 | S07 | `/consultations/:consultationId/questionnaire` | 방문상담 탭 |
| 방문상담 | S07 | `/consultations/:consultationId/visit` | 사진·발도장 탭 |
| 사진·발도장 | S08 | `/consultations/:consultationId/media` | 분석·보완 탭 |
| 분석·보완 | S08·S09 | `/consultations/:consultationId/analysis` | 최종결과 탭 |
| 최종결과 | S09 | `/consultations/:consultationId/result` | 고객 안내 인쇄 |
| 고객 안내 인쇄 | S12 | `/consultations/:consultationId/print` | 인쇄 후 최종결과로 복귀 |
| 환자 관리 | S03 | `/patients` | 신규 등록, 환자 상세 |
| 환자 등록 | S03 | `/patients/new` | 저장 후 환자 상세 |
| 환자 상세 | S04 | `/patients/:patientId` | 정보 수정, 신규 상담, 회차별 상담 작업 |
| 사용자 관리 | S10 | `/admin/users` | 사용자 등록·상태·초기화 |
| 기록 관리 | S11 | `/admin/records/consultations` | 상담 조회, 삭제 확인 대화상자 |
| 감사 기록 | S11 | `/admin/records/audit` | 주요 행위 조회, 상담·사용자 화면 이동 |
| 환자 질문지 | S06 | `/q/:token` | 제출 완료 화면 |
| 환자 질문 완료 | S06 | `/q/:token/complete` | 종료 안내 |

권한 없음, 찾을 수 없음, 일시 오류는 `/403`, `/404`, `/error` 공통 화면으로 연결합니다. 질문지의 만료·폐기·중복 제출은 별도 전역 메뉴 없이 `/q/:token` 문맥 안에서 상태 화면으로 보여줍니다.
`/admin/records`는 `/admin/records/consultations`로 이동합니다.

### 반응형 메뉴

- 1280px 이상: 좌측 고정 전역 메뉴와 상단 사용자 영역을 표시합니다.
- 768~1279px: 좌측 메뉴를 축소할 수 있고 상담 요약 패널도 접을 수 있게 합니다.
- 767px 이하: 전역 메뉴는 상단 메뉴 버튼으로 열고, 상담 작업 탭은 가로 스크롤 또는 현재 단계 선택 방식으로 제공합니다.
- 환자 질문지에는 전역 메뉴 대신 OUTFOOT 로고, 진행 단계, 임시 입력 상태만 표시합니다.

### 정적 화면 링크 완료 기준

- 모든 전역 메뉴와 목록의 주요 행·버튼이 위 경로의 정적 화면으로 이동합니다.
- 상담 작업의 다섯 탭, 환자 상세의 회차, 관리자 전용 메뉴가 서로 연결됩니다.
- 역할별 메뉴 노출과 담당자 여부에 따른 수정·읽기전용 상태, 빈 화면, 로딩, 오류, 권한 없음, 질문지 만료 상태를 합성 데이터로 확인할 수 있습니다.
- 발도장·AI 실행 이력, 최종본 개정 이력, 상담 기록·감사 기록 사이의 이동을 확인할 수 있습니다.
- 저장·업로드·분석·확정 버튼은 정적 단계에서 동작을 가장하지 않고 `기능 개발 단계에서 연결 예정` 상태를 명확히 표시합니다.
- 정적 화면과 mock 데이터는 실제 API 성공이나 분석 완료로 표시하지 않습니다.

## 상담 작업 화면

상단에는 환자명·마스킹 연락처·회차·상담유형·담당자·상태·주의신호·저장상태를 고정합니다. 탭은 `사전답변 / 방문상담 / 사진·발도장 / 분석·보완 / 최종결과` 다섯 개로 제한합니다. 우측 요약에는 주호소·현재 점수·주의신호·대표 부위·이전 회차 핵심만 표시합니다.

AI 분석 버튼은 필수정보·주의 확인·분석 입력 버전을 먼저 검사합니다. 최종확정 화면은 AI 원본을 수정하는 편집기가 아니라 별도의 최종 결과 필드입니다.

## 입력·오류 원칙

- 필수 오류는 항목 가까이에 표시하고 작성 내용을 잃지 않습니다.
- `없음`은 같은 복수 선택의 다른 값과 동시에 선택할 수 없습니다.
- `모름`, `미확인`, `해당없음`, `측정불가`를 0이나 정상으로 바꾸지 않습니다.
- 사진 품질 실패는 원인과 재촬영 또는 수동 확인 경로를 함께 표시합니다.
- 분석 미구성은 장애가 아니라 `샘플 검증 후 제공 예정` 상태로 표시합니다.
- 비활성 버튼만 두지 말고 실행 조건을 사용자가 이해할 수 있게 표시합니다.
- 삭제·최종확정·페이지 이탈은 확인을 받습니다. 임시저장은 명시적 버튼과 저장시각을 보여줍니다.

## 반응형 기준

시술자 화면은 1280px 이상을 기본으로 하고 768~1279px에서 우측 요약을 접을 수 있게 합니다. 767px 이하는 탭과 입력을 세로로 배치해 주요 조회·수정을 가능하게 합니다. 환자 질문지는 360px 이상 모바일을 우선합니다. 표는 작은 화면에서 카드로 전환하거나 가로 스크롤과 열 우선순위를 적용합니다.

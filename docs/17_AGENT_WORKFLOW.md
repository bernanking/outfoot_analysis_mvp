# Codex와 Claude Code 작업 방식

## 기본 원칙

Codex와 Claude Code는 같은 저장소와 문서를 사용하되 같은 파일을 동시에 수정하지 않습니다. 권장 흐름은 **Codex 구현 → Claude 검토 → Codex 수정·테스트 → 사용자 확인 → 커밋**입니다. 역할은 고정 의무가 아니지만 한 작업의 구현자와 검토자를 분리하면 누락을 찾기 쉽습니다.

## 작업 단위

`docs/15_TASKS.md`의 작업 ID를 요청에 포함합니다. 큰 작업은 DB, API, 화면, 테스트가 독립 검토 가능한 크기로 나눕니다. 각 에이전트는 시작 전에 `git status`와 관련 문서를 확인하고 기존 사용자 변경을 보존합니다.

## 구현 요청 템플릿

```text
T07을 진행해줘. AGENTS.md와 관련 문서를 먼저 읽고 기존 변경을 보존해.
범위는 버전된 질문 정의, 공개 링크의 공통/조건부 문항, 제출 API와 테스트야.
관리자 질문지 편집과 실제 환자 데이터는 제외해.
완료조건은 AT-04~08이며 실행한 테스트 결과와 미결정을 보고해.
```

## 검토 요청 템플릿

```text
T07 변경사항을 수정 없이 먼저 검토해줘.
질문지 분기, 없음 상호배제, 원본·버전 보존, 링크 권한,
중복 제출, 모바일 접근성과 테스트 누락을 우선 봐줘.
발견사항을 심각도·파일·재현·수정안으로 정리해줘.
```

## 수정 요청 템플릿

```text
검토 결과 중 합의된 항목을 수정하고 관련 테스트와 문서를 갱신해줘.
범위 밖 리팩터링은 하지 말고 완료 후 diff 요약과 실제 검증 결과를 알려줘.
```

## Git 운용

작업 시작 전 작은 체크포인트를 만들고 기능 브랜치 또는 깨끗한 작업단위를 사용합니다. 커밋 예시는 `feat(questionnaire): add conditional submission flow`, `fix(auth): enforce organization media access`, `docs(decision): record footprint provider choice`입니다. 리뷰 결과와 보류 사항을 코드 주석 대신 문서·이슈에 남깁니다.

## 비개발자 확인 방법

각 단계에서 사용자는 브라우저로 핵심 흐름을 확인합니다. 개발자는 테스트 URL, 테스트 계정, 확인할 시나리오, 알려진 미구현을 함께 제공합니다. ‘AI 분석 완료’와 ‘mock 결과 표시’를 명확히 구분합니다.

# Codex와 Claude Code 작업 방식

## 기본 원칙

Codex와 Claude Code는 같은 저장소와 문서를 사용하되 같은 파일을 동시에 수정하지 않습니다. 2026-09-30부터 권장 흐름은 **Claude 구현 → Codex 검토 → Claude 수정·테스트 → 사용자 확인 → 커밋**입니다. 한 작업의 구현자와 검토자를 분리해 누락을 찾기 쉽게 합니다. 역할을 바꿀 때는 이 문서와 작업 기록에 날짜와 함께 남깁니다.

| 역할 | 담당 | 하는 일 | 하지 않는 일 |
| --- | --- | --- | --- |
| 구현 | Claude Code | 작업 ID 단위 구현, 테스트·문서 갱신, 검증 결과 기록, Codex 검토 요청문 작성 | 사용자 요청 없는 커밋·푸시 |
| 검토 | Codex | 수정 없이 변경을 읽고 발견사항 보고 | 파일 수정, 커밋, 푸시 |
| 확인·결정 | 사용자 | 검토 결과 중 반영할 항목 결정, 브라우저 확인, 커밋 요청 | — |

2026-09-28까지는 Codex가 구현하고 Claude가 검토했습니다. T04A까지의 기록은 그 방식으로 진행된 작업입니다.

## 작업 단위

`docs/15_TASKS.md`의 작업 ID를 요청에 포함합니다. 큰 작업은 DB, API, 화면, 테스트가 독립 검토 가능한 크기로 나눕니다. 구현자는 시작 전에 `git status`와 관련 문서를 확인해 다른 에이전트가 수정 중인 파일이 없는지 보고 기존 사용자 변경을 보존합니다. 검토 중에는 구현자가 같은 파일을 고치지 않습니다.

## 구현 요청 템플릿 (사용자 → Claude)

```text
T07을 진행해줘. AGENTS.md와 관련 문서를 먼저 읽고 기존 변경을 보존해.
범위는 버전된 질문 정의, 공개 링크의 공통/조건부 문항, 제출 API와 테스트야.
관리자 질문지 편집과 실제 환자 데이터는 제외해.
완료조건은 AT-04~08이며 실행한 테스트 결과와 미결정을 보고하고,
끝나면 Codex 검토 요청문을 함께 작성해줘.
```

## 검토 요청 템플릿 (Claude가 작성 → 사용자가 Codex에 전달)

```text
T07 변경사항을 수정 없이 검토해줘. 파일 수정·커밋·푸시는 하지 마.
AGENTS.md와 관련 문서, docs/15_TASKS.md의 T07 기록을 먼저 읽고
git diff와 새로 생성된 파일을 확인해줘.
질문지 분기, 없음 상호배제, 원본·버전 보존, 링크 권한,
중복 제출, 모바일 접근성과 테스트 누락을 우선 봐줘.
발견사항을 심각도·파일:줄·재현·영향·수정안 순서로 정리하고,
추측은 확인된 결함과 구분해줘.
```

검토 요청문에는 변경 파일 목록, 근거 문서, 확정·제안·보류 구분, 특히 볼 위험을 적습니다. 구현자가 확인하지 않은 항목도 함께 알려 검토 범위에서 빠지지 않게 합니다.

## 수정 요청 템플릿 (사용자 → Claude)

```text
Codex 검토 결과 중 합의된 항목을 수정하고 관련 테스트와 문서를 갱신해줘.
(검토 결과 붙여넣기)
범위 밖 리팩터링은 하지 말고 완료 후 diff 요약과 실제 검증 결과,
수정하지 않은 항목과 이유를 알려줘. 필요하면 재검토 요청문도 작성해줘.
```

## Git 운용

작업 시작 전 작은 체크포인트를 만들고 기능 브랜치 또는 깨끗한 작업단위를 사용합니다. 커밋과 푸시는 사용자가 요청할 때만 구현자가 진행하며, 검토자는 Git을 조작하지 않습니다. 커밋 후에는 작업 트리와 원격 상태를 확인해 요청 범위를 넘은 푸시가 없는지 봅니다. 커밋 예시는 `feat(questionnaire): add conditional submission flow`, `fix(auth): enforce organization media access`, `docs(decision): record footprint provider choice`입니다. 리뷰 결과와 보류 사항을 코드 주석 대신 문서·이슈에 남깁니다.

## 비개발자 확인 방법

각 단계에서 사용자는 브라우저로 핵심 흐름을 확인합니다. 구현자는 테스트 URL, 테스트 계정, 확인할 시나리오, 알려진 미구현을 함께 제공합니다. ‘AI 분석 완료’와 ‘mock 결과 표시’를 명확히 구분합니다.

# 업무 흐름과 권한

## 상담 흐름

| 단계 | 상태 | 주체 | 완료 조건 | 다음 단계 |
| --- | --- | --- | --- | --- |
| 접수 | `INTAKE` | 시술자 | 환자·상담·담당자 생성 | 질문지 링크 발급 |
| 사전질문 | `QUESTIONNAIRE` | 환자 | 동의와 필수문항 제출 | 방문 상담 |
| 상담중 | `IN_VISIT` | 시술자 | 원답 확인, 방문 정보·필요 이미지 입력 | 분석 실행 |
| 분석검토 | `ANALYSIS_REVIEW` | 시술자 | 발도장 결과 보완, AI 결과 검토 | 최종확정 또는 보류 |
| 종결 | `FINALIZED` | 시술자 | 결론·고객안내·확정자 저장 | 회차 이력 조회 |

질문지 제출, 발도장 처리, AI 실행은 상담 상태와 별도 작업상태로 저장합니다. 처리 실패 때문에 상담 전체가 잘못 종결되지 않도록 합니다. `REFER_MEDICAL`과 `ON_HOLD`는 최종 결론 코드이며 별도 상담 단계가 아닙니다.

## 예외 흐름

- 링크 만료·재발급: 새 토큰을 만들고 기존 토큰은 폐기합니다. 이미 제출한 답변은 덮어쓰지 않습니다.
- 중복 제출: 동일 제출 키는 한 번만 저장하고 완료 화면을 다시 보여줍니다.
- 상담유형 변경: 환자 원선택을 보존하고 시술자 확인값을 별도로 저장합니다. 추가된 분기만 작성합니다.
- 발도장 누락·분석실패: 사유와 상태를 기록합니다. 의료기관 확인·보류는 종료할 수 있습니다. 일반 케어 확정 조건은 보류입니다.
- 입력 변경 후 분석: 분석에 사용한 입력 버전과 현재 버전이 다르면 `STALE`로 표시하고 최종 확정을 막습니다.
- AI 실패: 실패 응답을 정상 결과로 저장하지 않습니다. 같은 요청 키 재시도는 중복 결과를 만들지 않습니다.
- 동시수정: 클라이언트가 보낸 `version`이 현재와 다르면 409 충돌을 반환하고 다시 불러오게 합니다.

## 권한표

| 동작 | 환자 링크 | 시술자 | 관리자 |
| --- | ---: | ---: | ---: |
| 이번 상담 질문지 조회·제출 | 허용 | 조회 | 조회 |
| 다른 환자·회차 조회 | 금지 | 기관 내 조회 | 기관 내 조회 |
| 환자 등록·수정 | 금지 | 허용 | 허용 |
| 상담 생성 | 금지 | 허용 | 허용 |
| 상담 입력 수정 | 금지 | 담당자만 | 허용 |
| 사진·발도장 업로드 | 질문지 허용 유형만 | 담당자 | 허용 |
| 분석 실행·보완 | 금지 | 담당자 | 운영지원 목적 허용 제안 |
| 최종 시술 판단 확정 | 금지 | 담당 시술자 | 보류 O11 |
| 상담 삭제 | 금지 | 금지 | 사유 입력 후 논리삭제 |
| 시술자 계정 관리 | 금지 | 금지 | 허용 |

환자 링크는 환자 전체 페이지가 아니라 하나의 상담 질문지에만 접근합니다. 파일 URL 자체가 권한을 우회하지 않도록 다운로드도 API가 검사하거나 짧은 만료 URL을 발급합니다.

## 기록의 층위

| 층위 | 예시 | 수정 정책 |
| --- | --- | --- |
| 환자 원답 | 사전 질문 원문·선택값 | 제출본 불변, 정정은 확인값으로 |
| 방문 확인값 | 대면 확인·관찰·실측 | 담당자 수정, 버전 충돌 감지 |
| 분석 원본 | 발도장 자동값·AI 원본 | 실행별 불변 |
| 시술자 최종본 | 최종 결론·고객안내 | 확정본 개정 이력 보존 |
| 감사기록 | 로그인·삭제·확정·분석 실행 | 일반 사용자 수정 불가 |

# UI 디자인 시스템

## 방향

토스에서 느껴지는 명료한 정보계층, 충분한 여백, 쉬운 문장, 큰 클릭영역, 즉시 보이는 상태 피드백을 OUTFOOT 브랜드에 맞게 적용합니다. 공식 TDS의 React 전용 구현을 Vue에 그대로 가져오지 않습니다. PrimeVue 구성요소에 자체 디자인 토큰을 적용하는 방식을 확정 기준으로 사용합니다.

T04 구현에서는 라이선스 키 경고 없이 화면을 검토할 수 있도록 MIT 라이선스의 PrimeVue 4.5.5와 `@primeuix/themes` 2.0.3을 lockfile에 고정했습니다. 이는 구현 선택이며 PrimeVue의 이후 상용 버전 사용을 승인한 결정은 아닙니다.

## 글꼴과 글자 크기

- 글꼴 파일은 포함하지 않습니다. `Pretendard Variable`·`Pretendard`는 기기에 설치된 경우에만 쓰고, 없으면 `Apple SD Gothic Neo`(macOS·iOS), `Noto Sans KR`(Android), `Malgun Gothic`(Windows), `system-ui` 순으로 대체합니다. 외부 CDN을 쓰지 않습니다.
- 한국어는 `word-break: keep-all`로 어절 단위 줄바꿈을 하고 `overflow-wrap: break-word`로 긴 아이디·ID가 넘치지 않게 합니다.

| 역할 | 크기·굵기 | 조정 이유 |
| --- | --- | --- |
| 직원 화면 제목 | `clamp(24px, 1.6vw + 12px, 30px)` / 700 | 360px에서 24px, 1280px에서 약 30px. 32px는 1024px 표 화면에서 제목이 과하게 커 30px로 제한 |
| 카드·섹션 제목 | 18px / 700, 대화상자 20px | 기존 20px가 입력 라벨과의 차이가 커 카드 안 위계가 끊겨 18px로 조정 |
| 입력 라벨·선택 질문 제목(직원) | 14px / 600 | 기존 700은 모든 라벨이 제목처럼 보여 600으로 낮춤. legend도 같은 크기로 맞춤 |

| 문항 코드(V02·NV01 등) | 12px / 500, 보조문자색 | 라벨보다 낮은 비중 |

## 구성요소

버튼, 입력, 선택, 대화상자, 탭, 데이터테이블, 토스트는 PrimeVue 래퍼 컴포넌트로 노출해 앱 전체 API를 통일합니다. 업무 특화 구성요소는 `StatusBadge`, `SafetyFlag`, `PatientContextHeader`, `QuestionField`, `FootprintSlot`, `AnalysisProvenance`, `UnsavedChangesGuard`로 구성합니다.

## 상호작용 규칙

T04B 사전 UX 정리(1차)에서 정한 구현 기준입니다. 클라이언트 확정 사항이 아니라 화면 공통 규칙이며 피드백에 따라 조정합니다.

- 버튼: Primary는 주색 채움으로 화면의 대표 행동 한 개에만 씁니다. Secondary는 흰 바탕과 입력·버튼 경계, 위험 행동(삭제·사용 중지)은 위험색 테두리와 글자, 텍스트 링크는 주색 밑줄로 구분합니다. PrimeVue 기본 버튼도 `primary.700`(`#17324D`)을 주색으로 사용해 업무 화면 버튼과 맞춥니다.
- 조작 영역: 버튼·입력·선택·표 안 링크·텍스트 버튼·경로 안내 링크·질문지 선택 행은 최소 44px 높이를 사용합니다.
- 포커스: 링크·버튼·입력·선택·textarea·접기 요약·`tabindex` 요소에 3px 보조 청록 `:focus-visible` 테두리를 표시합니다.
- 화면 이동: 새 화면은 맨 위에서 시작하고 제목(h1)에 포커스를 옮깁니다. 뒤로가기·앞으로가기는 이전 스크롤 위치를 복원하고 포커스를 옮기지 않습니다. 같은 화면의 탭 이동은 탭에 포커스를 유지합니다.
- 경로 안내: 상위 항목은 링크로, 현재 화면은 `aria-current="page"` 문자로 표시합니다. 상세 화면에서도 해당 전역 메뉴를 활성으로 표시합니다.
- 안내 알림: 항상 보이는 정적 안내에는 알림 역할을 주지 않습니다. 화면 상태가 바뀌며 나타나는 안내만 알림으로 읽게 하며, 위험 톤은 `alert`, 그 외는 `status`를 사용합니다.
- 시안 검토 도구: 미리보기 역할은 상단, 화면 상태 예시는 각 화면 맨 아래의 기본으로 접힌 `시안 검토 도구`에 두고 업무 필터와 모양(점선)을 구분합니다. `화면 시안 · 합성 데이터` 표시와 현재 사용자 표시는 접어도 보입니다.
- 상태 배지: 글자를 유지하면서 대기(회색: 접수·사전질문), 진행(청록: 방문상담·분석 검토), 완료(초록: 종결)로 구분합니다. 주의(주황)는 주의신호 `미확인`·`확인 필요`에만 씁니다.
- 대상 확인 대화상자: 삭제·계정 사용 중지처럼 영향이 큰 작업은 대상의 식별 정보(환자·회차·상담일 또는 이름·아이디·역할·상태)를 대화상자 안에 다시 보여줍니다. 열리면 제목에 포커스를 두고 Tab을 대화상자 안에 가두며, Esc·닫기 후에는 연 버튼으로 포커스를 돌려줍니다.
- 목록: 기본 필터(검색·진행 상태·담당자)와 추가 필터를 나누고, 결과 건수·적용 조건·전체 초기화를 함께 보여줍니다. 조건은 주소에 남겨 상세 화면에서 돌아와도 유지합니다. 데이터 없음과 검색 결과 없음은 다른 문구와 행동으로 구분합니다.

## 시각 규칙 (2026-09-30 시각 디자인 정리)

- 카드 역할: 주 작업 카드는 흰 바탕·경계선, 참고 영역(환자 원답 보기·AI 참고·나머지 항목·중복 후보·결과 도구·대화상자 대상 정보)은 옅은 중립 바탕 `#F2F5F7`에 테두리 없이, 상담 요약은 같은 옅은 바탕에 라벨·값만 간결하게 둡니다. 카드 안에 같은 카드를 겹치지 않고 모바일 목록 카드는 구분선 목록으로 바꿨습니다. 로그인 카드의 그림자를 없애고 그림자는 대화상자·팝오버에만 둡니다.
- 페이지 간격: 경로 안내 줄(44px) → 제목(아래 8px) → 설명 → 본문(24px, 모바일 16px). 상단 대표 버튼은 경로 안내가 아니라 제목 줄에 맞춥니다. `.form-stack`은 16px 간격만 쓰고 안쪽 문단·그리드의 기본 여백은 0으로 둬 여백이 겹치지 않게 합니다. 카드 안쪽 여백은 PC 24px, 모바일 16px입니다.
- 입력 폭: 짧은 값(출생연도·나이·주당 횟수)은 최대 180px, 담당자·날짜는 최대 320px, 이름·전화번호·성별은 180~280px 열, 장문은 카드 폭입니다. 767px 이하는 모두 한 열로 쌓입니다.
- 입력 상태: 기본(`#7D8C99` 경계) · hover(`#52606D`) · focus-visible(3px 청록) · 비활성·조회 전용(`#EEF1F4` 바탕, `#4F5B67` 글자, 흐리게 하지 않음)을 구분합니다.
- 필수·선택: 질문 제목과 같은 줄에 작은 표시로 둡니다. 필수는 옅은 회색 알약, 선택은 테두리 없는 보조 글자이며 빨간색은 실제 오류 문구에만 씁니다. 라벨 안에서는 `.label-row`로 묶어 줄 위치가 항목마다 달라지지 않게 합니다.
- 선택 UI: 체크박스·라디오는 18px, `accent-color` 주색으로 통일합니다. 선택지 행(질문지·방문상담·결론·환자 선택)은 테두리 있는 행으로 두고, 선택되면 `#EAF1F6` 바탕과 주색 테두리를 더합니다. 체크·라디오 표시는 그대로 둬 색만으로 선택을 전달하지 않습니다. 결과 보기(초안·현재 확정본·이전 결과)는 하나의 묶음 안의 세그먼트로 표시합니다.
- 버튼 위계: 대표 행동만 주색 채움입니다. 뒤로가기·참고 화면 이동(`상담 목록으로`, `환자 상세`, `환자 목록으로`, 결과 화면의 인쇄 링크)은 밑줄 텍스트 링크(`quiet-link`)로 낮추고, 최종결과 하단의 `고객 안내 인쇄 화면`은 Secondary로 둬 최종확정보다 약하게 보이게 했습니다. 비활성 버튼은 투명도 대신 비활성 바탕·경계·글자로 구분하고, 비활성 Primary는 점선 경계를 씁니다.
- 기능 미연결 표시: 버튼 이름에서 `· 기능 연결 예정`을 빼고, 행동 영역 가까이에 주의색 원 표시가 있는 `pending-note`(예: `저장 기능 연결 예정`)를 둡니다. 버튼은 계속 비활성입니다.
- 하단 행동 영역: 상담 작업 하단은 상단 구분선·배경·옅은 그림자가 있는 고정 영역입니다. PC는 `변경 취소`(왼쪽) · `임시저장` · 안내 · 다음 단계(오른쪽), 767px 이하는 보조 행동 2열 → 안내 → 대표 행동 전체 폭의 의도적인 2열 배치입니다. 키보드 포커스가 고정 영역 뒤로 가면 가려진 만큼만 스크롤합니다(`app/stickyFocus.ts`). 대화상자 안의 포커스, 마우스·터치 직후의 포커스, 고정 영역 안·아래의 요소는 스크롤하지 않습니다.
- 탭: 활성 탭은 청록 밑줄과 옅은 바탕(`#EAF1F6`), 탭 이름 15px/600(활성 700), 진행 상태 12px/500입니다. 진행 상태 색은 완료(초록)·진행(청록)·대기(보조문자)·보완 필요(주의 갈색 `#7A4A11`, 600)로 나누고 글자를 항상 함께 씁니다. 767px 이하는 다섯 탭을 같은 폭의 3열 격자로 둡니다.
- 접기: 추가 필터·환자 원답 보기·나머지 항목·AI 참고·촬영 안내·답변 묶음·시안 검토 도구·상담 요약에 같은 꺾쇠 표시를 씁니다. 접힘은 오른쪽(▶), 펼침은 아래(▼)이며 요약 줄은 주색 600으로 일반 제목과 구분합니다.
- 배지: 높이 24px, 좌우 10px, 12px/600. 발도장 필요 여부는 좌우 칸마다 반복하지 않고 좌우 발도장 영역 제목 옆에 한 번만 표시합니다.
- 표: 머리글은 13px/600, 옅은 바탕과 강한 구분선, 행은 위아래 10px·세로 가운데 정렬입니다. 표 안 링크는 44px 조작 영역을 유지하되 위아래를 겹쳐 행 높이를 키우지 않습니다(1024px 행 높이 95px → 71px). 날짜는 `tabular-nums`와 줄바꿈 금지, 환자명은 주정보, 회차·유형·연락처는 보조 줄입니다.
- 반응형 표시: `.mobile-only`·`.desktop-only`는 파일 마지막에서 `(width < 768px)`·`(width >= 768px)` 범위 문법과 `!important`로 적용해 768px 미만은 카드만, 이상은 표만 보입니다(R1). 한 경계로 나눠 소수 너비에서도 둘 다 보이거나 둘 다 숨지 않습니다.
- 표 스크롤 영역(`.table-scroll`)은 위치 기준(`position: relative`)을 가져 숨긴 머리글(`.sr-only`)이 페이지 전체 폭을 늘리지 않습니다(V1).
- 질문지 답변 확인에서 보조 답변(상세 설명·대표 발톱·주당 횟수)은 해당 문항 아래 들여 쓴 점선 구분 행으로 표시합니다.
- 사진 슬롯: 좌우 칸은 제목(L/R 표시와 글자) → 상태 배지 → `이미지 미리보기 자리 · 합성 시안` 점선 영역(단순 사진 아이콘) → 다음 행동 설명 → 버튼 순서이고, 버튼은 칸 아래 같은 기준선에 둡니다. 실제 발도장 그림·사진은 만들지 않습니다.
- 모바일 상단: 한 줄(메뉴 · `시안` ─ 현재 사용자 · `시안 도구`)로 줄였습니다(높이 125px → 61px). 화면낭독기에는 `시안 검토 도구` 전체 이름을 읽힙니다.
- 아이콘: 새 라이브러리 없이 사진 자리의 단순 inline SVG만 사용합니다.

- 색상만으로 상태를 전달하지 않고 아이콘·문자를 함께 씁니다.
- 모든 입력은 label·오류문·도움말과 연결합니다.
- 키보드 포커스와 44px 수준의 터치영역을 제공합니다.
- 전화번호·민감정보는 기본 마스킹합니다.
- 분석 값 옆에 출처 `자동분석 / AI 관찰 / 시술자 입력`과 측정상태를 표시합니다.

## 금지

공식 TDS 이름·상표·에셋을 허가 없이 OUTFOOT 자체 디자인인 것처럼 배포하지 않습니다. 더미 통계나 가짜 AI 점수를 실제 데이터처럼 표현하지 않습니다. 경고를 팝업에만 숨기거나 모든 카드에 과도한 그림자를 쓰지 않습니다.

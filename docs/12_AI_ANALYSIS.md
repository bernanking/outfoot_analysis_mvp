# AI 종합분석 설계

## 역할

AI는 사전질문, 방문 확인값, 발도장 분석·품질, 시술자 보완정보를 이용해 **상담 검토 초안**을 만듭니다. 진단·시술 확정 주체가 아니며 시술자가 최종본을 작성합니다.

기존 개인 ChatGPT 또는 GPT 대화방을 웹에서 직접 호출하지 않습니다. 클라이언트가 제공하는 역할지침, 전문자료, 판단기준, 우수·수정·오류 사례, 금지표현을 사용권 확인 후 API용 지침·검색자료·평가 사례로 재구성합니다. 자료를 업로드했다고 모델이 영구 학습되었다고 표현하지 않습니다.

## 분석 모드

- `SUMMARY_ONLY`: 상담 요약, 정보 부족, 추가 질문, 주의 확인. 전문 기준이 미승인일 때 사용 가능.
- `CARE_SUPPORT`: 위 항목과 시술·케어 방향 초안. O04·O06과 평가 통과 후 운영.

## 입력 묶음

환자의 직접 식별정보는 제외하고 사례 ID, 상담유형, 원답, 방문 확인값, 안전확인 상태, 이미지별 품질·관찰·측정값, 시술자 보완을 전달합니다. 값마다 출처와 상태를 유지합니다. 원본 이미지를 AI에 보낼지는 제공자 선택·동의 범위에 따라 결정합니다.

## 출력 구조

```json
{
  "schemaVersion": "1.0",
  "caseSummary": "",
  "footFindings": { "left": [], "right": [], "comparison": [] },
  "evidence": [{ "statement": "", "sourceRefs": ["C04", "PV09"] }],
  "missingInformation": [],
  "followUpQuestions": [],
  "safetyConsiderations": [],
  "careDirectionDraft": [],
  "patientFriendlyDraft": "",
  "limitations": []
}
```

구조화 출력은 형식 검증 수단일 뿐 내용 정확도를 보장하지 않습니다. 서버는 schema, enum, 길이, 출처 참조의 존재를 검증합니다. 근거가 없거나 서로 모순되는 결과는 검토 필요로 표시합니다.

## 버전과 원본 보존

각 실행에는 모델 식별자, promptVersion, knowledgeVersion, schemaVersion, 입력 스냅샷 해시, 실행자·시각, 사용량, 원시출력, 파싱결과를 기록합니다. 새로운 입력이나 전문자료 변경은 기존 결과를 덮지 않고 새 실행을 만듭니다. 현재 입력과 해시가 다르면 `STALE`입니다.

최종 리포트는 AI 원본의 편집본이 아니라 별도 개정입니다. 고객 안내에는 내부 추론·위험한 확정 표현·환자에게 불필요한 전문 메모를 자동 노출하지 않습니다.

## 실패와 비용

타임아웃·제공자 제한·파싱실패·안전 거부를 구분해 저장하고 제한 횟수만 재시도합니다. 같은 idempotency key로 우리 쪽 중복 작업 생성을 막습니다. 외부 공급자가 같은 요청 키로 중복 실행·과금을 막는지는 공급자 선택(O06) 때 공식 문서로 확인하고, 확인 전에는 지원하지 않는다고 가정합니다. 요청을 보낸 뒤 응답을 잃어 성공 여부가 불명확하면 자동 재호출하지 않고 `OUTCOME_UNKNOWN`으로 두며, 담당자가 확인한 뒤 새 시도를 만듭니다. 전송 직전에 `SENDING`을 먼저 기록하므로, 실행기가 전송 직후나 응답 저장 전에 멈춰도 회수 단계에서 `OUTCOME_UNKNOWN`으로 처리됩니다. 임대 토큰은 결과 덮어쓰기만 막고 중복 과금을 막지 못합니다. AI 호출은 Supabase Edge Function의 서버 경로에서만 하고 키는 함수 비밀값으로만 둡니다. 실행 방식(작업 테이블·선점·회수)은 [아키텍처](08_ARCHITECTURE.md#분석ai-작업-처리)를 따르며, "정확히 한 번 실행"을 보장한다고 표현하지 않습니다. 모델·이미지 상세수준·건당 토큰과 비용은 평가 후 정합니다. 운영에는 일별·월별 사용량과 오류율을 기록하되 요청 원문 개인정보는 로그에 남기지 않습니다.

## 평가

대표 사례에 대해 시술자가 `정확 / 수정필요 / 위험 / 근거부족`으로 평가하고 필수 확인 누락, 금지표현, 사실 불일치, 케어 범위 일탈, 구조 오류를 기록합니다. 보류 기준을 통과하기 전 `CARE_SUPPORT`를 운영 기본값으로 열지 않습니다. 실제 운영 중에도 AI 결과는 표본 검토합니다.

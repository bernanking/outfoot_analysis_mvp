# 검수 기준과 테스트 시나리오

## 검수 원칙

기능은 실제 저장된 데이터와 권한으로 검증합니다. 목업·하드코딩 응답·미구성 분석기는 구현 완료로 인정하지 않습니다. 보류 기능은 합의되지 않았음을 명확히 표시하면 그 외 MVP 검수를 진행할 수 있습니다.

## 핵심 시나리오

| ID | 시나리오 | 기대 결과 |
| --- | --- | --- |
| AT-01 | 관리자가 시술자 생성·비활성 | 활성 로그인 가능, 비활성은 즉시 거부 |
| AT-02 | 환자 중복 후보가 있는 등록 | 전화 정규화 기준 후보 안내, 사용자가 선택 |
| AT-03 | 상담 생성·링크 발급 | 상담에 귀속된 비추측 토큰, 링크 복사 가능 |
| AT-04 | NAIL 질문 제출 | 공통+발톱만 표시, 원답·문항·동의 버전 보존 |
| AT-05 | PAIN_INSOLE 질문 제출 | 공통+통증만 표시, 현재/최고 점수 구분 |
| AT-06 | 두 유형 제출 | 공통은 한 번, 두 분기 저장, 발·발가락 매핑 명확 |
| AT-07 | 없음과 다른 값을 동시 선택 | 입력 단계에서 차단·설명 |
| AT-08 | 만료·폐기·중복 제출 | 기존 데이터 훼손 없이 알맞은 상태 표시 |
| AT-09 | 원답 대면 정정 | original 보존, confirmed와 확인자 저장 |
| AT-10 | 사진 업로드·권한 | 유효 이미지만 저장, 다른 기관·환자 링크 접근 거부 |
| AT-11 | 좌우 발도장 | 두 파일·방향·품질·처리상태가 각각 저장 |
| AT-12 | 분석 미구성·실패 | 가짜 결과 없이 이유·재시도/보완 경로 표시 |
| AT-13 | 분석 보완 | 자동 원본 불변, 보완값·사유·작성자 저장 |
| AT-14 | AI 실행 | 식별정보 제외, schema 검증, 원본·버전 저장 |
| AT-15 | 입력 변경 후 AI 결과 | 결과 `STALE`, 해당 결과로 최종확정 차단 |
| AT-16 | AI 실패·중복클릭 | 정상결과 미생성, 제한 재시도, 한 작업만 실행 |
| AT-17 | 최종확정 | AI 원본과 별도 최종본, 확정자·시각 저장 |
| AT-18 | 의료기관 우선·보류 | AI 케어 초안 없이 사유·주의 안내로 종료 가능 |
| AT-19 | 수정 충돌 | 최신값 조용한 덮어쓰기 없이 409·재불러오기 |
| AT-20 | 관리자 삭제 | 시술자 거부, 관리자 사유·감사기록·일반목록 제외 |
| AT-21 | 회차 이력·인쇄 | 환자별 회차 열기, 확정 고객안내만 인쇄 |
| AT-22 | 모바일 질문지 | 360px에서 가로 잘림 없이 작성·오류·완료 가능 |

## 자동 테스트 최소선

- unit: 문항 분기, `없음` 상호배제, 권한 규칙, 상태전이, 입력 해시, 오래됨 판정, AI schema.
- API integration: 로그인, 기관 격리, 제출 원자성, 업로드 권한, 낙관적 잠금, 논리삭제.
- E2E: AT-03~06 중 대표 흐름, 상담 저장, AI mock 성공·실패, 최종확정, 관리자 삭제.
- migration: 빈 DB와 이전 스키마 양쪽에서 적용, seed는 합성 데이터만 사용.

## 분석 검수 게이트

샘플 검증 전에는 업로드·상태·어댑터 계약만 검수합니다. 실제 정량값과 스크리닝은 O01·O02에서 확정한 입력유형, 기준값, 독립 검증 사례, 허용오차, 실패기준으로 별도 검수합니다. 정확도가 부족한 항목은 지원목록에서 제외하거나 수동확인으로 낮춥니다.

AI `CARE_SUPPORT`는 승인 사례에서 누락·금지표현·근거·위험 평가를 통과하고 시술자가 승인한 후 운영합니다. 테스트 수치와 합격선은 사례 확보 후 문서에 추가합니다.

## 완료 정의

코드·DB 마이그레이션·환경 예시·테스트·관련 문서가 함께 갱신되고, 보안 차단 이슈가 없으며, 담당자가 스테이징에서 핵심 시나리오를 확인해야 완료입니다. 화면만 존재하거나 API가 더미 데이터를 반환하면 완료가 아닙니다.

# 발도장 분석 기술검증 계획

## 현재 결정

발도장 분석을 OpenCV, OpenAI 이미지 API 또는 병행 방식 중 무엇으로 구현할지 정하지 않았습니다. 실제 좌우 샘플과 기준값이 오면 다시 검토합니다. 따라서 이 문서는 확정 알고리즘이 아니라 시험·의사결정 기준입니다.

## 입력 유형 구분

| 입력 | 알 수 있는 것 | 알 수 없는 것 |
| --- | --- | --- |
| 일반 A4의 발 위치 네 점 | A4 모서리가 보이면 표시점 간 거리·비율 후보 | 접촉면적·아치 족적지표·압력 |
| 일반 A4의 실제 접촉 발도장 | 선명한 흔적이면 접촉형태·면적·족적지표 후보 | 절대 압력 kPa, 3D·보행 |
| 범용 격자 발도장 | 격자 규격 검증 시 크기 보정 후보 | 용지 규격 미확정 시 정확한 실측 |
| 엑스바디 결과 스크린샷 | 장비가 표시한 결과의 텍스트·형태 참고 | 원시 센서값·알고리즘 재현 |

네 점 다각형 면적을 족저 접촉면적으로 표시하지 않습니다. 이미지 농도를 압력으로 환산하지 않습니다.

## 후보 방식

| 방식 | 강점 | 한계 | 적합 역할 |
| --- | --- | --- | --- |
| 규칙형 영상처리 | 동일 입력에서 계산 재현, 좌표·면적 계산 가능 | 촬영·도장 변화에 민감, 전처리 필요 | 보정·영역·정량 계산 후보 |
| OpenAI 이미지 분석 | 형태 설명·품질 의견·문진 통합에 유리 | 정밀 좌표·mm·면적의 반복성 보장 어려움 | 관찰 초안·품질 보조 후보 |
| 병행 | 계산과 언어 해석 분리 | 비용·구조 증가 | 정량+설명 모두 필요할 때 |
| 시술자 수동확인 | 실패 복구와 현장 지식 반영 | 시간·평가자 편차 | 모든 방식의 필수 안전장치 |

## 검증 자료

같은 방식으로 만든 좌우 원본, 빈 용지·촬영 환경, 실제 자 또는 승인된 기준방법으로 얻은 길이·폭, 전문가가 표시한 접촉영역·유형, 성공·경계·실패 사례, 반복촬영 자료가 필요합니다. 개인정보를 제거하고 사례 ID로 연결합니다.

## 실험 절차

1. 지원할 입력 유형과 최소 촬영 가이드를 고정합니다.
2. train/test가 아니라 개발용과 독립 검증용 사례를 나눕니다.
3. 품질 판정, 용지 보정, 영역 추출, 지표 계산, 스크리닝을 각각 평가합니다.
4. 길이·폭은 mm 오차, 면적·비율은 정의에 맞는 오차, 영역은 합의한 겹침 지표, 유형은 혼동표로 비교합니다.
5. 왼쪽·오른쪽, 정상·경계·실패 사례별 결과를 봅니다.
6. 지원·보조·미지원 항목을 정하고 O02를 갱신합니다.

표본 수·목표 오차를 임의 확정하지 않습니다. 결과가 기준을 만족하지 못하면 해당 수치 대신 `측정불가` 또는 시술자 수동 입력을 제공합니다.

## 생산 인터페이스

공급자는 `analyze(input) -> normalizedResult` 계약을 구현합니다. 공급자 코드는 `NOT_CONFIGURED`, `MANUAL_REVIEW`, `OPENCV`, `OPENAI_VISION`, `HYBRID`로 정규화하고 어댑터를 교체할 수 있게 하며 UI·DB가 공급자 내부 형식에 의존하지 않게 합니다.

결과에는 입력 해시, 공급자·버전, 품질·실패 이유, 값별 측정 상태, 단위·방법, 스크리닝 기준 버전, 실행시각을 포함합니다. 시술자 보완값은 원본 위에 덮어쓰지 않습니다.

Edge Functions는 요청당 CPU 2초·메모리 256MB 제한이 있어 무거운 영상처리를 그 안에서 실행하지 않습니다. 실행부는 작업 테이블을 선점·보고하는 같은 계약을 쓰므로, OpenCV 등이 필요하면 실행부만 외부 서버 프로세스로 분리할 수 있습니다([아키텍처](08_ARCHITECTURE.md#분석ai-작업-처리)). 분리 여부와 실행 위치는 O01·O02 결정 후 정합니다.

# 프론트 화면별 내용 구성 계획

버전 1.0 · 2026-09-22 · 대상: T04·T04A 정적 화면 및 페이지 연결

이 문서는 기능 API를 연결하기 전 클라이언트와 화면 기획을 검토하기 위한 정적 프론트 기준입니다. 화면에는 합성 데이터만 사용하고, 저장·업로드·분석·확정이 실제로 처리된 것처럼 표현하지 않습니다. 메뉴와 URL은 [메뉴와 화면 명세](04_SCREENS.md)를 기준으로 합니다.

## 공통 화면 틀

### 직원용 화면

| 영역 | 내용 |
| --- | --- |
| 좌측 메뉴 | OUTFOOT 로고, 상담 관리, 환자 관리, 관리자 전용 운영 관리 |
| 상단 영역 | 현재 기관, 사용자명·역할, 로그아웃, 모바일 메뉴 버튼 |
| 페이지 제목 영역 | 경로 안내(상위 항목 링크), 제목, 한 줄 설명, 화면의 대표 행동 버튼 1개 |
| 본문 | 검색·필터, 업무 카드, 표 또는 입력 폼 |
| 상태 피드백 | 로딩, 빈 결과, 오류, 권한 없음, 저장 여부를 같은 위치와 문구 체계로 표시 |

정적 프론트에는 상단에 `화면 시안 · 합성 데이터` 배지와 미리보기 현재 사용자 이름·역할을 표시합니다. 시술자 시안의 현재 사용자는 `시술자 김`, 관리자 시안은 `관리자 박`으로 표시하고, 담당자 비교도 같은 미리보기 사용자 상태를 사용합니다. 미리보기 역할은 상단, 화면별 상태 예시는 각 화면 맨 아래의 기본으로 접힌 `시안 검토 도구`에 모아 업무 필터와 구분합니다. 상담·환자 상세 화면에서도 해당 전역 메뉴를 활성으로 표시합니다. 기능이 연결되지 않은 버튼은 비활성화만 하지 않고 `기능 개발 단계에서 연결됩니다`라는 안내를 제공합니다.

### 상담 작업 공통 틀

상담 화면은 아래 세 부분을 모든 탭에서 유지합니다.

1. 환자 컨텍스트: 환자명, 마스킹 전화번호, 회차, 상담 유형, 담당자, 상담 상태, 주의신호, 저장 상태
2. 작업 탭: 사전답변, 방문상담, 사진·발도장, 분석·보완, 최종결과
3. 요약 패널: 주호소, 현재 불편점수, 대표 부위, 확인할 주의신호, 이전 회차 핵심

1081px 이상에서는 요약 패널을 우측에 표시하고, 1080px 이하에서는 본문 위의 접이식 영역(기본 접힘)으로 이동합니다(P16 제안). 탭 옆에는 각 탭의 내용에서 계산한 업무 상태를 표시합니다(T04B 제안): 사전답변 `제출 대기`·`확인 필요`·`확인 완료`, 방문상담 `시작 전`·`작성 중`·`확인 완료`, 사진·발도장 `미등록`·`선택 항목`·`유형 확인 전`·`한쪽 누락`·`보완 필요`·`확인 완료`, 분석·보완 `미구성`·`보완 필요`·`재실행 필요`, 최종결과 `미작성`·`작성 중`·`종결`. 상담 단계만으로 이전 탭을 모두 완료 처리하지 않고, 미구성·미수행·선택 항목을 완료와 구분합니다. 사전답변과 방문상담 상태는 **저장된 방문 기록**에서 읽습니다(T04B 후속 제안): 방문상담은 저장 기록 없음 `시작 전`, 저장 기록이 작성 중 `작성 중`, 저장 기록이 확인 완료 `확인 완료`이고, 사전답변은 제출 후 `방문 시 확인할 항목`이 모두 저장된 확인값(미확인 제외)을 가지면 `확인 완료`, 아니면 `확인 필요`입니다. 사전답변·방문상담의 완료 상태와 저장값 요약(저장된 방문 기록, 방문 시 확인할 항목의 확인값, 상담 요약의 현재 불편 정도)은 저장 기록 기준이라 저장하지 않은 입력으로 바뀌지 않고, 그 입력은 상단 저장 상태(`저장하지 않은 변경 있음`)로만 표시하며, 글자를 입력했다는 사실만으로 확인 완료가 되지 않습니다. 반면 사진·발도장 필요 여부(사진·발도장 탭 상태, 분석·보완의 좌우 발도장 항목)는 방문상담에서 고른 시술자 확인 유형 초안을 저장 전에도 즉시 반영합니다. 정적 시안의 저장 기록과 그 상태값은 합성 fixture(`visitRecord`, 시안 전용)이고, 실제 확인 완료 기준은 T08에서 확인값·저장 기록으로 정하며 O04·O05 결정 전입니다. 새로운 진행 차단 규칙은 아닙니다. 모든 탭은 같은 하단 행동 영역(변경 취소·임시저장·다음 단계)을 씁니다. 입력은 상담별 로컬 초안으로 보관해 탭·결과 보기 전환으로 사라지지 않고, `변경 취소`는 초기값(저장된 기록이 있으면 그 값)으로 되돌립니다. 저장하지 않은 변경이 있으면 탭·목록 등으로 이동하기 전에 확인하고, `저장하지 않고 이동`은 변경을 버리고 이동합니다(P14 제안).

환자·상담 기록은 같은 기관 직원이 조회할 수 있지만 수정 권한은 별도로 표시합니다. 담당 시술자와 관리자는 허용 범위에서 입력할 수 있고, 담당자가 아닌 시술자는 상단에 `조회 전용 · 담당자만 수정할 수 있습니다` 배너를 표시합니다. 관리자는 상담 입력을 수정할 수 있지만 최종 시술 판단 확정은 O11이 결정되기 전까지 사용할 수 없습니다.

## S01 로그인

경로: `/login`

### 화면 구성

- 좌측 또는 상단: OUTFOOT 로고와 `족부 상담 기록을 한곳에서 관리하세요` 안내
- 로그인 카드: 아이디, 비밀번호, 비밀번호 표시 전환, 로그인 버튼
- 보조 안내: 계정 발급과 초기화는 관리자에게 요청하도록 안내
- 하단: 운영기관·개인정보 관련 문구가 확정되기 전에는 임시 문구임을 표시

### 상태와 연결

- 기본, 입력 오류, 로그인 처리 중, 로그인 실패, 비활성 계정 상태
- 성공 시 `/consultations`로 이동
- 공개 회원가입, 소셜 로그인, 비밀번호 찾기 이메일 화면은 만들지 않음

## S02 상담 관리

경로: `/consultations`

### 화면 구성

- 제목: `상담 관리`
- 대표 행동: `신규 상담 접수`
- 검색: 환자명 또는 전화번호 뒤 네 자리
- 필터: 상담 상태, 상담 유형, 담당자, 주의신호, 최근 상담 기간
- 빠른 범위: 전체, 진행 중, 종결
- 목록 열: 환자, 회차·상담일, 상담 유형, 현재 단계, 질문지 상태, 담당자, 주의신호, 최근 수정
- 행 행동: 상담 열기, 환자 상세 보기. 담당자가 아닌 상담은 `조회 전용`으로 표시

### 상태와 연결

- 신규 접수 → `/consultations/new`
- 행 선택 → 해당 상담의 현재 작업 탭
- 환자명 선택 → `/patients/:patientId`
- 빈 결과, 필터 결과 없음, 로딩, 목록 오류를 별도 상태로 구성
- 합성 상담은 `INTAKE`, `QUESTIONNAIRE`, `IN_VISIT`, `ANALYSIS_REVIEW`, `FINALIZED`를 하나 이상 포함
- 질문지를 제출하지 않은 회차의 상담 유형은 `환자 미선택`으로 표시하고 유형 필터에서도 별도로 찾을 수 있게 함

## S03 환자 관리·등록

- 목록 경로: `/patients`
- 등록 경로: `/patients/new`

### 환자 목록

- 제목: `환자 관리`
- 대표 행동: `신규 환자 등록`
- 검색: 이름, 전화번호
- 목록 열: 환자명, 마스킹 전화번호, 성별, 출생연도 또는 등록 시 나이, 최근 상담일, 상담 회차, 담당자
- 행 행동: 환자 상세 열기, 새 상담 접수

### 환자 등록

- 기본정보: 이름, 전화번호, 성별, 출생연도 또는 현재 나이 입력 방식 선택
- 중복 확인 영역: 전화번호 정규화 기준의 후보 환자 목록
- 후보 행동: 기존 환자 열기, 중복 아님을 확인하고 등록 계속
- 하단 행동: 취소, 등록 후 상세 보기, 등록 후 상담 접수

### 상태와 연결

- 환자 행 → `/patients/:patientId`
- 새 상담 → `/consultations/new?patientId=:patientId`
- 필수 입력 오류, 중복 후보 있음, 검색 결과 없음, 등록 처리 중 상태

## S04 환자 상세

경로: `/patients/:patientId`

### 화면 구성

- 상단: 환자명, 기본 식별정보, `정보 수정`, `새 상담 접수`
- 기본정보 카드: 마스킹 연락처, 성별, 출생연도 또는 등록 시 나이, 등록일, 최근 수정일
- 상담 회차: 회차, 날짜, 상담 유형, 담당자, 현재 상태, 최종 결론, 주의신호
- 각 회차에 현재 사용자의 `수정 가능` 또는 `조회 전용` 권한을 표시
- 회차 정렬: 최신순을 기본으로 하며 상태 필터 제공
- 관리자 보조 표시: 논리삭제된 상담을 포함해 볼 수 있는 권한 안내

### 상태와 연결

- 회차 선택 → 해당 상담 작업 화면
- 새 상담 → `/consultations/new?patientId=:patientId`
- 정보 수정은 같은 화면의 패널 또는 대화상자로 구성
- 상담 이력이 없는 상태, 수정 충돌 안내, 조회 오류 상태
- 과거 사진 비교와 회차 일괄 복사 기능은 배치하지 않음

## S05 상담 접수

- 신규 경로: `/consultations/new`
- 접수 상세 경로: `/consultations/:consultationId/intake`

### 신규 접수 구성

1. 환자 선택: 기존 환자 검색 또는 신규 환자 등록으로 이동
2. 담당자 선택: 기본값은 로그인한 시술자, 관리자는 기관 내 담당자 선택 가능
3. 접수 확인: 환자, 담당자, 생성할 상담 회차 확인

환자의 상담 유형은 질문지에서 환자가 선택하므로 접수 단계에서 확정값으로 입력하지 않습니다.

### 접수 상세 구성

- 상담 요약: 환자, 회차, 담당자, 생성일, 현재 상태
- 질문지 링크 카드: 미발급, 활성, 만료 예정, 제출 완료, 만료, 폐기 상태
- 링크 정보: 만료시각, 최근 발급시각, 제출시각, 제출 가능 횟수
- 행동: 링크 발급, 복사, 재발급
- 안내: 자동 문자·카카오·이메일 발송은 제공하지 않으며 복사한 링크를 직원이 전달

### 상태와 연결

- 제출 전에는 링크 관리와 상담 취소 이동 경로를 제공
- 제출 완료 후 `사전답변 보기` → `/consultations/:consultationId/questionnaire`
- 재발급 시 이전 링크가 폐기된다는 확인 대화상자
- 링크는 한 번 제출하면 다시 제출할 수 없음을 안내하고, 72시간 만료는 운영 확정 전 `제안값`으로 표시
- 정적 화면에서는 복사 UI만 시연하고 실제 유효 토큰이 생성됐다고 표시하지 않음

## S06 환자 사전질문지

- 작성 경로: `/q/:token`
- 완료 경로: `/q/:token/complete`

환자 질문지는 360px 모바일을 기준으로 하며 직원용 메뉴와 환자 과거정보를 표시하지 않습니다.

### 단계 구성

| 단계 | 제목 | 포함 내용 |
| --- | --- | --- |
| 1 | 안내와 동의 | 질문지 목적, 예상 작성 흐름, 개인정보·외부 AI 안내 초안, 필수 동의 |
| 2 | 상담 내용 | C01 상담 유형, C02 가장 불편한 점, C03 시작 시점, C04 현재 불편 정도 |
| 3 | 안전 확인 | C05~C10 주의신호, 건강상태, 복용약, 수술·외상 |
| 4 | 생활과 목표 | C11~C13 신발, 서기·걷기 시간, 상담 목표 |
| 5 | 발톱 질문 3단계 | `NAIL` 선택 시 N01~N13을 발톱 상태·통증과 관리·주변과 신발로 나눔. 발가락은 L1~L5·R1~R5를 한글 위치와 함께 표시 |
| 6 | 통증·인솔 질문 3단계 | `PAIN_INSOLE` 선택 시 P01~P15를 불편 부위와 느낌·생활 속 불편·신발과 인솔로 나눔 |
| 7 | 사진 | `NAIL` 선택 시 N14 선택 사진 |
| 8 | 답변 확인 | 단계별 답변 요약·수정 링크, 필수 미응답 안내, 제출 |

T04B에서 긴 유형별 단계를 나누고 답변 확인 단계를 분리했습니다(P15 제안). 세부는 [질문지 명세](05_QUESTIONNAIRES.md)를 따릅니다.

두 유형을 선택하면 공통 단계는 한 번만 표시하고 발톱과 통증·인솔 단계를 모두 표시합니다. `없음`은 다른 복수 선택과 동시에 선택되지 않게 설명합니다.

### 공통 요소와 상태

- 상단: OUTFOOT 로고, 현재 단계, 전체 진행 정도
- 하단 고정 행동: 이전, 다음, 제출
- 사진 단계: 미리보기, 교체, 삭제, 업로드 재시도, 허용 형식·남은 첨부 수 표시
- 입력 오류는 해당 질문 가까이에 표시하고 첫 오류로 이동
- 뒤로 이동해 수정 가능, 제출 후에는 직접 수정 불가
- 완료 화면: 제출시각, 방문 시 다시 확인한다는 안내, 창 닫기
- 만료, 폐기, 이미 제출, 네트워크 오류, 파일 오류 상태
- 상담 대상 확인 방식과 동의문 원문은 O07 및 클라이언트 피드백 전까지 `확정 예정`으로 표시
- 파일당 10MiB·공개 폼 사진 4개 제한은 운영 확정 전 `제안값`으로 표시하고 설정값으로 변경할 수 있게 구성
- 미성년자·보호자 흐름은 O12 결정 전 제공하지 않으며 정적 시안에는 성인 합성 데이터만 사용

## S07 상담 작업: 사전답변·방문상담

- 사전답변 경로: `/consultations/:consultationId/questionnaire`
- 방문상담 경로: `/consultations/:consultationId/visit`

### 사전답변 탭

- 질문지 상태: 미발급, 작성 대기, 제출 완료, 만료
- 제출 정보: 제출시각, 질문지 버전, 동의 버전
- 답변 그룹: 공통, 발톱, 통증·인솔, 첨부 사진
- 상담 유형: 환자가 선택한 원본 유형과 시술자가 확인한 유형을 분리해 표시
- 시술자 유형 보완: 원선택은 변경하지 않고 확인값에 유형을 추가하며, 새로 추가된 유형의 분기 문항만 작성. 정적 시안에서는 방문상담 첫 영역 `상담 유형 확인`에서 환자 원선택(읽기 전용)과 시술자 확인 유형(발톱·통증·인솔, 둘 다 선택 가능)을 나란히 두고, 환자가 고른 유형은 해제할 수 없게 합니다. 사전답변에는 확인 유형을 표시만 합니다.
- 각 항목: 환자 원답을 읽기전용으로 표시합니다. 확인값은 방문상담에서 입력하고 사전답변에는 `방문 시 확인할 항목`과 해당 입력 위치 링크를 둡니다(P13 제안). 미제출이면 답변 목록 대신 링크 상태와 링크 관리로 안내합니다.
- 정정 시: 확인값, 정정 이유, 확인자, 확인시각을 구분
- 주의신호: 출처 질문, 확인 상태, 확인 메모
- 행동: 다음 단계(방문상담)로 이동. 사전답변 자체에는 저장할 입력이 없습니다.
- `방문 시 확인할 항목`은 저장된 방문 기록의 확인값이 있으면 `확인됨 · 값`(예: `확인됨 · 없음`)을, 없으면 해당 방문상담 입력 위치 링크를 표시하고, 제목 옆에 남은 건수를 표시합니다. 탭 상태와 같은 목록을 씁니다(T04B 후속 제안).

### 방문상담 탭

- 공통 확인: V01~V10
- 발톱 상담 선택 시: NV01~NV10
- 통증·인솔 상담 선택 시: PV01~PV12
- 원답과 현재 확인값을 나란히 비교해야 하는 항목은 2열 구조 사용
- 사실 관찰과 시술자 판단을 별도 입력 영역으로 구분
- `없음`, `모름`, `미확인`, `미측정`, `해당없음`을 각각 선택 가능하게 구성
- 하단 고정 행동: 변경 취소, 임시저장, 사진·발도장으로 이동
- 첫 영역에 `저장된 방문 기록`(저장 기록 없음·작성 중·확인 완료와 저장시각)을 표시합니다. 입력 초기값과 `변경 취소`의 복귀값은 저장된 기록이며, 상담 요약의 현재 불편 정도도 저장값을 씁니다(정적 시안은 합성 예시).

### 상태

- 저장 전 변경 있음, 저장 중, 저장됨·시각, 필수 입력 누락, 수정 충돌, 주의 확인 필요
- 담당자가 아닌 시술자는 모든 입력과 실행 행동을 읽기전용으로 표시
- 의료기관 우선 또는 보류 선택 시 이유와 안전 안내 영역을 우선 표시
- 일반 케어 확정 조건은 O04·O05 확정 전 안내 상태로 유지

## S08 사진·발도장

경로: `/consultations/:consultationId/media`

### 화면 구성

- 촬영 안내: 허용 형식, 파일 크기, 좌우 구분, 재촬영 기준
- 발톱 사진: 전체 발과 문제 발톱 사진 슬롯, 선택 항목 표시
- 발도장: 왼쪽과 오른쪽을 분리한 동일 구조의 업로드 슬롯
- 발톱 단독 상담은 발도장을 `선택`, 통증·인솔 상담은 좌우 발도장을 `기본 필요`로 표시
- 각 파일 카드: 미리보기, 유형, 좌우, 발가락 번호, 업로드 상태, 품질 상태, 등록자·시각
- 이미지 보기: 확대, 회전 보기, 원본 다운로드 권한 안내
- 불가 사유: 촬영불가, 한쪽 누락, 품질부족, 기타 사유와 메모
- 파일 행동: 교체, 삭제, 재업로드, 실패 상세 보기, 재촬영 안내 보기

### 상태와 연결

- 빈 슬롯, 업로드 중, 검증 중, 완료, 형식 오류, 용량 초과, 품질 확인 필요, 실패
- 품질 실패에는 실패 이유와 `재촬영`, `다른 파일 선택`, `수동 확인 기록` 경로를 함께 표시
- 좌우가 뒤바뀌지 않도록 슬롯 제목과 색상 외 문자 표기를 함께 사용
- 담당자가 아닌 시술자는 원본 보기만 허용하고 업로드·삭제·교체 행동을 제공하지 않음
- 정적 단계에서는 로컬 미리보기 예시만 사용하고 R2 저장 완료로 표시하지 않음
- 발도장 필요 여부와 발톱 사진 칸은 방문상담의 시술자 확인 유형(환자 원선택 포함)을 기준으로 표시하며, 탭 옆 상태도 같은 기준을 씁니다. 확인 유형이 없으면 `유형 확인 후 결정`으로 표시함
- 다음 → `/consultations/:consultationId/analysis`

## S09 분석·보완 및 최종결과

- 분석 경로: `/consultations/:consultationId/analysis`
- 최종결과 경로: `/consultations/:consultationId/result`

### 분석·보완 탭

1. 실행 전 점검
   - 사전답변, 방문상담, 좌우 이미지, 주의신호 확인 상태
   - 좌우 발도장은 사진·발도장 탭과 같은 시술자 확인 유형 기준입니다. 통증·인솔 포함은 `기본 필요`로 미등록·한쪽 누락·품질 확인 필요를 확인할 항목에 넣고, 발톱 단독은 `선택 항목`으로 표시해 확인할 항목 수에 넣지 않으며, 유형 미확인은 `필요 여부 미정`으로 방문상담의 유형 확인으로 안내합니다. 사전답변 행은 제출 여부만 보므로 `제출됨`으로 표시합니다. 표시 기준이며 실행·확정 차단 조건이 아닙니다(T04B 후속 제안).
   - 부족한 항목과 이동 링크
2. 발도장 분석
   - 공급자·버전, 실행시각, 입력 버전, 품질 상태
   - 왼쪽·오른쪽 결과와 좌우 비교
   - 값별 `측정`, `추정`, `미제공`, `측정불가`, `해당없음` 표시
   - 샘플 검증 전에는 `분석 방식 미구성`과 제공 예정 범위만 표시
   - 실행 이력에서 현재 실행과 과거 실행을 선택하고 실행자·상태·입력 스냅샷·실패 이유를 확인
3. 시술자 보완
   - 자동 원본은 읽기전용
   - 보완값, 근거·이유, 작성자·시각을 별도 입력
4. AI 상담 검토
   - 실행 전 전달 범위와 식별정보 제외 안내
   - 상담 요약, 근거, 누락정보, 추가질문, 주의사항, 한계
   - 전문 기준 승인 전 `SUMMARY_ONLY`만 표시
   - 실행별 모델, promptVersion, knowledgeVersion, schemaVersion, 입력 스냅샷, 실행자·시각을 출처 정보로 표시
   - 과거 실행과 원본 결과를 덮어쓰지 않고 실행 이력에서 선택해 조회

분석 상태는 대기, 실행 중, 실패, 미구성, 완료, 오래됨으로 구성합니다. 입력 변경으로 오래된 결과에는 최종확정에 사용할 수 없다는 안내와 재실행 행동을 표시합니다. 실패 상태는 입력 부족, 타임아웃, 공급자 제한, 출력 형식 오류, 안전 거부를 구분하고 가능한 경우 `다시 실행` 또는 `수동 보완` 행동을 제공합니다. 실행 중에는 중복 실행을 막고 현재 작업 상태를 표시하며, 같은 재시도 요청이 새 결과를 중복 생성하지 않는다는 안내를 제공합니다.

### 최종결과 탭

- 참고 영역: AI 원본 요약과 근거를 읽기전용으로 표시
- 최종 결론: 관리 검토, 추가 확인 필요, 의료기관 우선, 보류
- 내부 결론: 시술자 업무용 메모
- 고객 안내: 쉬운 표현의 현재 상태, 관리 방향, 주의사항
- 추후 확인: 날짜, 주기 또는 미정 사유
- 확정 정보: 개정 번호, 확정자, 확정시각, 사용한 분석 버전
- 개정 이력: 개정 번호, 확정자·시각, 사용한 AI 실행, 현재 개정 여부를 목록으로 표시
- 행동: 임시저장, 최종확정, 새 개정 작성, 이전 개정 보기, 고객 안내 인쇄

AI 원본을 직접 수정하는 편집기는 만들지 않습니다. 일반 관리 계획은 최신 AI 검토본만 사용하며, 오래된 분석·미확인 주의신호 등 차단 조건은 이유와 해결 링크를 함께 표시합니다. `의료기관 우선`과 `보류`는 AI 케어 초안과 추후 확인 날짜가 없어도 이유, 안전 안내, 확인 담당자를 입력해 종결할 수 있는 별도 확정 흐름을 제공합니다. 일반 케어에서 AI 장애 중 수동 확정은 P12·O05 결정 전 제공하지 않습니다. 확정 전 확인 대화상자를 제공하며 관리자의 최종확정 권한은 O11 확정 전 관리자 화면에서 제공하지 않습니다. 담당자가 아닌 시술자는 AI 원본과 확정본을 조회할 수 있지만 실행·보완·확정·개정 행동은 사용할 수 없습니다.

## S10 사용자 관리

경로: `/admin/users`

### 화면 구성

- 제목: `사용자 관리`, 관리자 전용 표시
- 대표 행동: `사용자 등록`
- 검색·필터: 이름, 로그인 아이디, 역할, 계정 상태
- 목록 열: 이름, 로그인 아이디, 역할, 상태, 최근 로그인, 등록일
- 사용자 등록: 이름, 로그인 아이디, 역할, 초기 비밀번호 설정 방식
- 행 행동: 상세 보기, 활성·비활성 전환, 비밀번호 초기화

### 상태

- 활성, 비활성, 로그인 이력 없음
- 비활성화 확인에는 해당 사용자의 기존 세션이 즉시 종료된다는 영향을 표시
- 비밀번호 초기화 결과는 관리자가 안전한 경로로 직접 전달하며 이메일 자동발송으로 표현하지 않음
- 자기 계정 비활성화 등 운영상 제한이 필요한 행동은 확인 안내
- 공개가입·이메일 자동초대 기능은 배치하지 않음

## S11 기록·감사 관리 및 삭제 확인

- 상담 기록 경로: `/admin/records/consultations`
- 감사 기록 경로: `/admin/records/audit`

### 상담 기록

- 검색·필터: 환자, 담당자, 상담 상태, 상담 유형, 삭제 여부, 기간
- 목록 열: 환자, 회차, 상담 유형, 담당자, 상태, 최종 결론, 삭제 상태, 최근 수정
- 행 행동: 상담 열기, 삭제 확인, 삭제 정보 보기
- 삭제된 상담은 일반 상담 목록에서 제외하고 이 화면에서 상태와 사유를 표시

### 감사 기록

- 검색·필터: 행위자, 행위 유형, 대상 유형, 결과, 발생 기간
- 목록 열: 발생시각, 행위자, 행위, 대상, 결과, 요청 ID
- 상세: 민감 원문을 제외한 변경 요약, 상담·환자·사용자 화면 이동
- 포함 행위: 로그인 성공·실패, 계정 상태 변경, 환자·상담 핵심정보 변경, 링크 발급·폐기, 질문지 제출, 파일 등록, 발도장·AI 실행, 최종확정·개정, 상담 삭제
- 감사기록은 조회 전용이며 환자 답변 원문, 비밀번호, 토큰, 공급자 키를 표시하지 않음

### 삭제 확인 대화상자

- 대상 환자·회차·상담일
- 영향을 받는 질문지, 이미지, 분석, 최종본이 연결된 기록임을 안내
- 논리삭제이며 보유정책에 따른 실제 파기와 다르다는 설명
- 필수 삭제 사유
- 행동: 취소, 상담 삭제

시술자 역할에서는 기록 관리 메뉴와 삭제 행동을 표시하지 않습니다. 삭제 처리 중, 권한 오류, 이미 삭제됨, 완료 상태를 구성합니다.
정적 관리자 화면에서 사용자 관리·상담 기록·감사 기록 탭을 바꾸면 앞 탭의 검색어와 선택한 행은 초기화해 다른 탭의 확인 영역이 열리지 않게 합니다.

## S12 고객 안내 인쇄

경로: `/consultations/:consultationId/print`

### 화면 구성

- OUTFOOT·기관 기본정보
- 고객명과 상담일, 상담 회차, 상담 유형
- 시술자가 확정한 현재 상태 요약
- 확정된 관리 방향과 홈케어 안내
- 주의사항과 의료기관 확인 안내
- 추후 확인 일정 또는 미정 사유
- 확정자, 확정일, 문서 개정 번호

AI 원본, 내부 메모, 감사정보, 확정되지 않은 분석 수치는 인쇄하지 않습니다. 화면 상단에 확정본 개정 선택, `인쇄`, `최종결과로 돌아가기`를 제공하고 실제 인쇄 CSS에서는 메뉴와 버튼을 숨깁니다. 과거 개정에는 `이전 개정` 표시를 넣고 현재 확정본과 혼동하지 않게 합니다. 확정본이 없거나 오래된 개정을 연 경우 안내 상태를 표시합니다. 확정본 존재 기준은 최종결과 탭과 같습니다. 정적 시안에서는 종결 상담만 현재·이전 결과(결과 2·결과 1) 합성 예시를 가지며, 미확정 상담은 문서·결과 선택 대신 `인쇄할 확정본이 없습니다`와 `최종결과로 돌아가기`를 표시합니다. 길이 확인용 중립 문장은 확정본 예시 안에서만 보입니다. 삭제된 상담은 관리자 조회 전용 안내를 유지합니다.

## 공통 보조 화면

| 경로 | 내용 | 주요 행동 |
| --- | --- | --- |
| `/403` | 현재 계정으로 접근할 수 없음 | 상담 목록으로 이동 |
| `/404` | 화면 또는 기록을 찾을 수 없음 | 이전 화면, 상담 목록 |
| `/error` | 일시적인 오류와 요청 ID | 다시 시도, 상담 목록 |

페이지 이탈 확인, 저장 충돌, 최종확정, 링크 재발급, 계정 비활성화, 상담 삭제는 공통 대화상자 패턴을 사용합니다. 성공·오류 알림은 색상과 함께 아이콘·문자를 사용합니다.

## 합성 데이터 구성

정적 프론트에서는 아래 상태를 확인할 수 있는 합성 fixture를 준비합니다.

- 역할: 시술자, 관리자
- 권한: 담당 시술자 수정, 다른 시술자 조회 전용, 관리자 수정·최종확정 제한
- 상담 유형: 발톱, 통증·인솔, 두 유형 함께
- 상담 단계: 접수, 사전질문, 상담중, 분석검토, 종결
- 질문지 링크: 미발급, 활성, 만료, 제출 완료
- 주의신호: 없음, 미확인, 확인 완료
- 이미지: 좌우 완료, 한쪽 누락, 품질 확인 필요
- 분석: 미구성, 입력 부족, 실행 중, 공급자 실패, 출력 형식 오류, 완료 구조 예시, 오래됨, 실행 이력
- 최종본: 미작성, 임시저장, 의료기관 우선·보류 종결, 확정, 과거·현재 개정
- 운영: 활성·비활성 사용자, 상담 논리삭제, 민감정보를 제외한 감사기록

합성 환자명과 상담 정보에는 화면 시안임을 표시합니다. 분석 완료 구조 예시는 상태와 레이아웃 검토용이며 임상 수치·정상 판정·점수를 넣지 않습니다.

## 정적 화면 제작 순서

1. 공통 레이아웃, 디자인 토큰, 전역 메뉴, 합성 fixture, `/403`·`/404`·`/error`
2. S01 로그인, S02 상담 관리, S03 환자 관리, S04 환자 상세, S05 상담 접수
3. 상담 작업 공통 틀과 S07 사전답변·방문상담, S08 사진·발도장, S09 분석·최종결과
4. 모바일 우선 S06 환자 질문지와 제출·만료 상태
5. 관리자 전용 S10 사용자 관리, S11 상담·감사 기록 관리와 S12 고객 안내 인쇄
6. 빈 화면·로딩·오류·권한·충돌 등 상태 변형, 전체 페이지 링크와 반응형 검수

각 순서가 끝날 때 페이지 링크와 360px·768px·1280px 화면을 확인합니다. T04A 완료 시에는 모든 경로가 열리고 주요 버튼이 다음 정적 화면으로 연결되어야 하며, API 성공을 전제로 한 기능 검수는 하지 않습니다.
